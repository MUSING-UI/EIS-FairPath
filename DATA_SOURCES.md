# DBLP data sources

The shared raw file is the [MIT BigDND DBLP publication dataset](https://projects.csail.mit.edu/dnd/DBLP/), available as [dblp.json.gz](https://projects.csail.mit.edu/dnd/DBLP/dblp.json.gz). It is a simplified historical DBLP export of publication keys, author lists, and years. The archive contains 4,215,613 publication records.

Bundled source: `data/raw/dblp.json.gz`, 94,924,986 bytes.

The raw archive is tracked with Git LFS. Run `git lfs pull` after cloning to obtain the full file before verification or data reconstruction. Its byte size and SHA-256 remain unchanged. The three processed domain graphs and calibrated prediction models are stored directly in Git, so explanation inference can use them independently of the raw archive.

SHA-256: `1503ae44f951af5567c57db477f0598f2efeccd2cca27371be1912612089037e`.

## Full domain selectors

| Domain | Inclusive years | Venue key prefixes |
| --- | --- | --- |
| Mining / IR | 2003–2010 | `conf/kdd/`, `conf/icdm/`, `conf/sdm/`, `conf/sigir/`, `conf/cikm/`, `conf/wsdm/` |
| NLP | 1991–2013 | `conf/acl/`, `conf/emnlp/`, `conf/naacl/`, `conf/coling/`, `conf/eacl/` |
| Vision | 2002–2009 | `conf/cvpr/`, `conf/iccv/`, `conf/eccv/`, `conf/bmvc/`, `conf/icpr/` |

The three processed files retain all valid records matching these selectors. Query generation and model sampling leave those files unchanged. “Complete domain” refers to these historical venue/year windows in the supplied export.

Each processed publication stores its key, year, venue, normalized author IDs, and event kind. Author names undergo Unicode NFKC normalization, case folding, whitespace normalization, and SHA-256 hashing. The resulting `dblp-name:` IDs identify normalized names; the source archive retains the original author strings.

The graph has author, paper, and venue nodes. Relations are writes/written-by, published-in/publishes, and collaboration. Reverse message routes share a physical-event identifier. Fixed 16-dimensional identity features and annual activity masks are regenerated by `eis_fairpath.graph`.

Internal/Cross roles derive from historical graph communities. The input data contain bibliographic records and structural roles.
